# C9 prompts (Claude Code)

## Build (plan mode)

Read CLAUDE.md, README.md, docs/adr/001-stack.md and the current src/ first.

This is the C9 milestone ("All at once"): make the confusion meter real-time.

- Add a column lectures.min_present (default 5) with a hand-written migration
  that runs safely on the existing /data database. The demo lecture uses 2.
- GET /l/:id/events : a server-sent events stream. On connect, send the current state.
  After any change, send it again to every open connection for that lecture.
  State = { present: open connections for this lecture, live: taps in the last 60 seconds,
  shown: present >= min_present }. Send a heartbeat comment every 20 seconds.
- Taps fade: when a tap passes 60 seconds old, push the new state without waiting for another tap.
- /l/:id : add a live gauge (people here, and how many are lost right now, or
  "Waiting for N more people" when not shown). Add a small script that uses EventSource
  to update it, and submits the tap with fetch so the page doesn't reload.
  Without JavaScript the existing form must still work.
- The gauge text must be in an aria-live region so screen readers hear changes.
- Keep the open connections in memory (one machine, see ADR 001).
- Tests in spec/, using inject("baseUrl"): a tap shows up on an open /events stream
  within 1 second, present goes up when a second stream connects, and
  shown is false below min_present. Propose how to test the 60-second fade without
  a test that waits 60 seconds.

Not in scope yet: browser IDs, one-tap-per-browser, the lecturer view. Those are C10.
Commit in small steps. Ask before deploying, pushing or tagging.
Show me the plan first.
