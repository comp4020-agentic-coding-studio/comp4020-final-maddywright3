# C8 prompt (Claude Code, plan mode)

Read CLAUDE.md, README.md, fly.toml, the Dockerfile, spec/README.md,
spec/invariants.test.ts and spec/global-setup.ts before planning anything.

This is the C8 milestone ("It's alive!") of a lecture confusion meter: students
tap "I'm lost" during a lecture, and the taps are saved so they're still there
when anyone comes back. Replace the busybox placeholder with:

Server
- src/server.ts on Node 24, run directly as TypeScript, using node:http and node:sqlite
- Listen on 0.0.0.0:$PORT (default 8080)
- Database at $DATA_DIR/meter.db (DATA_DIR defaults to ./data locally; set it to /data in the Dockerfile)
- Tables: lectures(id TEXT PRIMARY KEY, title, created_at) and taps(id INTEGER PRIMARY KEY, lecture_id REFERENCES lectures, created_at)
- On startup, create a lecture with id "demo" and title "Demo lecture" if it doesn't already exist

Pages, all rendered on the server so they work with no JavaScript
- GET / : one-paragraph intro, plus links to /l/demo and /readme/
- GET /l/:id : the lecture title, a large "I'm lost" button, the total tap count, and the tap times newest first
- POST /l/:id/tap : saves a tap, then redirects (303) back to /l/:id
- GET /readme/ : README.md rendered with marked, and files in docs/ served so README images work
- Unknown lecture or path : 404 page
- Every page has lang="en", a <main> landmark, a single <h1>, and works at 390x844 and 1920x1080

Docker
- Dockerfile on node:24-slim with pnpm, production dependencies only, copying README.md and docs/ into the image
- Keep everything in fly.toml exactly as it is

Tests in spec/, written like spec/invariants.test.ts (use inject("baseUrl"), don't start your own server)
- /l/demo answers 200 and shows a tap count
- POSTing a tap to /l/demo increases the count by one
- /l/does-not-exist answers 404
- Persistence across a restart can't be tested this way. Suggest a manual check I can run against Fly instead.

Don't add features I haven't listed: no accounts, no live updates, no lecturer view yet. Those come in later milestones.

Show me the plan first, including the dependencies you'd add and why. Don't write code until I approve it.
